# Canonical required ops-api action surface.
#
# Single source of truth for the source-side pre-deploy gates
# (scripts/deploy-edge-function.sh via require_ops_actions, and
# scripts/check-ops-api-source-actions.sh) and for deployed-binary post-deploy
# verification via action-surface iteration, which lives in
# scripts/smoke-ops-api-action-surface.sh and is invoked by both
# scripts/smoke-edge-functions.sh and the production deploy workflow.
#
# Format: one action name per line. Lines starting with '#' and blank lines are
# ignored. Add the action name (no quotes, no commas), nothing else.
#
# An action line may carry an optional post-deploy probe policy in a trailing
# comment. Every other reader of this file strips comments, so the policy only
# changes how scripts/smoke-ops-api-action-surface.sh proves recognition:
#
#   (no policy)           GET the action; if the deployed binary says "Unknown
#                         action", retry once as a POST with an empty body.
#   probe=jwt-fail-closed GET only. Recognition means the deployed binary
#                         refused the API-key caller at authTrade with
#                         "Login required" — a tenant read that answers with
#                         data instead is drift, not a pass.
#   probe=bounded-refusal GET only, with probe-args appended. Recognition means
#                         the handler refused a deliberately invalid bound
#                         before touching any business data.
#   probe=source-only     Never called against production. Use this when a bare
#                         no-argument call mutates business data, so the only
#                         honest recognition proof is the pre-deploy source gate
#                         (scripts/check-ops-api-source-actions.sh).
#   probe-args=<query>    Extra query string appended to the GET probe.
#
# Declare the policy here rather than in the smoke script: an action the script
# has never heard of must not silently inherit "fire it at production".
#
# When you add a handler to supabase/functions/ops-api/index.ts that JARVIS,
# the cockpit, or the canonical reader (sw_job_context_v2) depends on, add it
# here too. The deploy guard then refuses to deploy a source tree missing the
# action; smoke then refuses to mark the deploy green if the deployed binary
# fails the probe policy declared for that action above.
#
# Drift history: on 2026-05-14 the deployed binary returned "Unknown action"
# for ops_api_version, daily_coverage_audit, and assemble_job_dossier despite
# all three being in source. Codex redeployed canonical to fix. This file +
# the smoke iteration are the post-deploy detective control.
