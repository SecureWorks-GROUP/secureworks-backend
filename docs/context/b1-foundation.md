# Context switch and daily run custody (B1)

Implements target sections 3b/4/6 and build contracts 1/5. No production action has run. The switch is seeded on as approved; deploy through the normal reviewed migration path. Existing operator off values survive reapply.

Scheduled monitor-inbox-poll (capture) and contact-matching (attribution) stop posting when disabled. Unknown command shapes abort deployment. Invoice synchronization, including xero-invoice-sync cron and ops trigger_xero_sync, continues operational finance updates when capture is off; only its business_events emission checks capture. Webhook capture is a B2 integration seam.

SQL helpers, all revoked from anonymous/authenticated callers:

- `automation_lane_enabled(lane text) -> boolean`: strict fail closed; service role allowed.
- `automation_switch_cron_lanes() -> table(cron_jobname,lane)`: two classified jobs.
- `automation_switch_wrap_cron_jobs()` / `automation_switch_unwrap_cron_jobs()`: idempotent command changes, postgres only. Missing cron extension reports skipped; unexpected existing commands abort.
- `claim_context_extraction_run(p_job_id uuid,p_run_date date,p_phase text) -> jsonb`: outcome claimed/done/busy/paused, run object. Today's Perth date only. Claims establish custody, consume no model budget and remain available at the call cap. Phase is attribution/extraction/bucket. New lease is 30 minutes with a fresh UUID token.
- `reserve_context_model_call(p_phase text,p_run_id uuid,p_lease_token uuid) -> jsonb`: atomic, service-role-only provider admission. Phase must be extraction/attribution/bucket. Extraction requires the run UUID and current lease UUID from claim; optional job-scoped attribution/bucket calls supply both, otherwise both are explicitly null. A supplied run must match the phase, current Perth day and a running, unexpired lease. Wrong/expired/replaced/completed fences return `outcome: stale`; invalid argument combinations raise. Lane disabled, missing switch or switch read error returns `paused`. Extraction uses the extraction switch; attribution and bucket use attribution, all respecting all_stop. Every phase shares 400 reservations per Perth day, determined by the server clock after admission locking. Admission 400 returns `reserved`; 401 returns `cap`. Success includes reservation_id, run_date and ordinal. Reservations are append-only for service-role callers.
- `finish_context_extraction_run(p_run_id uuid,p_lease_token uuid,p_status text,p_event_ids uuid[],p_tokens_in integer,p_facts_new integer,p_facts_superseded integer,p_facts_retracted integer,p_error text,p_retry_at timestamptz) -> boolean`: running, unexpired token required; statuses done/failed/skipped. Successful extraction acknowledges supplied event UUIDs for this job and `luna_v2`. Failure retains retry time without event acknowledgments. Wrong/expired token returns false. B3 must call this INSIDE the fact revision transaction and raise if false, so facts and acknowledgments commit together.
- `claim_context_pass(p_run_date date) -> jsonb`: same outcomes except cap; returns pass object and top-level lease_token. Starts at/after 06:00 Perth, 3-hour lease. Persisted retry_at survives restart.
- `renew_context_pass(p_run_date date,p_lease_token uuid) -> boolean`: extends a live lease 3 hours. Worker renews between jobs and must stop on false.
- `finish_context_pass(p_run_date date,p_lease_token uuid,p_status text,p_retry_at timestamptz,p_error text) -> boolean`: fenced completion; updates daily model-call reservation count. Phase markers attribution_done_at/bucket_done_at let worker avoid repeating completed phases while another lane is paused; marker updates must check the same active lease.

`context_extraction_event_receipts` primary key is (event_id,job_id,extractor_version). B2 candidate queries use missing receipts, not timestamps: delayed attribution and the remainder after 25 survive. B3 owns source snapshot validation before transactional persistence. J1 must keep model deadlines below the run lease and never execute under a failed claim. Claims do not themselves invoke a model or production business effect.

Exact provider caller contract (Jarvis/root must implement before release): claim custody where applicable, prepare the complete request, then call reserve_context_model_call immediately before EACH provider invocation, including attribution, bucket calls and all retries. Await successful RPC transaction commit and invoke once only for an observed `reserved` response. Never reuse a reservation for another call. On paused/cap/stale/error/timeout, do not invoke. An ambiguous reservation response, provider timeout, crash or post-model failure is never refunded; a retry needs a fresh reservation. Do not wrap reservation and the network call in a transaction that can later roll back. The budget conservatively counts reservations, including calls whose execution cannot be confirmed; it never counts only successful results. A switch stops new reservations, not already admitted network work. No B1 caller invokes the provider; downstream integration remains a release prerequisite.

Rollbacks retain operator decisions, attempts and receipts; they stop admissions and unwrap scheduled commands. They deliberately do not drop audit tables. Restore code in the same rollback operation; remaining new callers fail closed.
